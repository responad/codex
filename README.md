# JOOTEK 폴리오 시공입찰DB

공공 건축·건설 프로젝트를 **입찰공고 → 첨부파일 → 실제 수요 → 조달 패키지 → 납품·영업기회**로 연결하는 인터랙티브 프론트엔드 프로토타입입니다.

## 구현된 핵심 경험

- 프로젝트 기준 / 공고 기준 전환
- 전체 / 입찰 참여 / 낙찰·계약 / 자재 영업기회 / 관심 프로젝트
- 기본 보기 / 입찰 참여 보기 / 자재·영업 보기
- 기본필터 + 상세필터 + 검색 + 정렬
- 프로젝트 기회점수와 우리회사 적합도 분리
- 공사내역서·물량내역서·시방서·일람표 분석 신호
- **실제 자재·장비 수요(Fact)** 와 **AI 자재 영업기회(Inference)** 완전 분리
- 관급 / 사급, 작업물량 / 제품수량 / 계약수량 구분
- 원문 항목을 조달·납품 패키지로 묶어 영업기회화
- 자재·장비·전문공사·렌탈·운송·철거·시험 등 공급범위 확장 고려
- 특이 스펙 및 대체가능성
- 낙찰 후 영업타이밍과 추천대상
- 우측 500px 3Depth 상세패널
- 프로젝트 타임라인, 미니지도, 주택지도 이동 UI
- 공사원가계산, 첨부파일, 나라장터 공식 원문 CTA
- 관심 프로젝트 및 업무기회 저장(localStorage 데모)

## 핵심 데이터 모델

```text
Project
  → Tender
    → Attachment
      → ExtractedItem
        → NormalizedItem
          → ProcurementPackage
            → SalesOpportunity
```

### 데이터 규칙

- `레미콘타설 5㎥`(작업물량)과 `레미콘 사급 7㎥`(제품수량)를 합산하지 않음.
- 실제 자재는 공사내역서/물량내역서/시방서/일람표 등 공식 근거를 유지함.
- AI 추론 자재는 공식 데이터와 별도 저장하고 화면에서도 별도 색상/배지로 표시함.
- 가능한 경우 파일명·시트명·원문 행/셀 위치·상위 공종 문맥·추출 신뢰도를 함께 보존함.

## 실행

```bash
npm test
python3 -m http.server 8080
```

브라우저에서 `http://localhost:8080`.

## 배포

`main`에 병합되면 GitHub Actions가 정적 검증을 수행하고 GitHub Pages 배포를 시도합니다.
