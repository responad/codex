# JOOTEK 폴리오 시공입찰DB

JOOTEK의 **시공입찰DB / 건축 프로젝트 인텔리전스** 프로토타입입니다.

단순히 나라장터 공고를 다시 보여주는 것이 아니라, 공고와 첨부파일을 함께 분석해 다음 세 가지를 한 제품 안에서 해결하는 것을 목표로 합니다.

1. **입찰 인텔리전스** — 내 회사가 참여할 수 있는 공사를 빠르게 찾기
2. **실제 수요 데이터** — 공사내역서·물량내역서·시방서에서 실제 자재/장비/공종 수요 추출
3. **영업 인텔리전스** — 낙찰 이후 누구에게 무엇을 언제 영업해야 하는지 제안

## 실행

외부 의존성이 없는 정적 프로토타입입니다.

```bash
python3 -m http.server 8080
```

브라우저에서 `http://localhost:8080`을 엽니다.

- 실제 자재와 AI 추론 자재의 명확한 분리
- 첨부파일 분석 상태
- 공사내역서 기반 실제 자재·수량

## 핵심 데이터 파이프라인

```text
Project
  → Tender
    → Attachment
      → ExtractedItem
        → NormalizedItem
          → ProcurementPackage
            → SalesOpportunity
```

### ExtractedItem에서 반드시 보존할 값

- 원본 파일 ID
- 파일명
- 시트명
- 원문 행/셀 위치
- 상위 공종 문맥
- 원문 품명
- 원문 규격
- 단위
- 수량
- 원문 관급/사급 표기
- 추출 신뢰도

### NormalizedItem 유형

- 제품·자재 납품
- 장비·기계 납품
- 공급+시공
- 전문공사·시공
- 건설장비·렌탈
- 운송·물류
- 철거·폐기
- 시험·검사·시운전
- 조경·식재
- 원가·법정경비(영업기회 제외)

## 중요한 데이터 규칙

`레미콘타설 5㎥`와 `레미콘(사급) 7㎥`를 12㎥의 동일 자재 수요로 합산하면 안 됩니다. 원문 항목을 최소한 다음처럼 구분해야 합니다.

- 작업물량
- 제품수량
- 계약수량

또한 `공식 문서에서 확인된 실제 자재`와 `AI가 추가로 추론한 자재 영업기회`는 UI와 데이터 모델 모두에서 별도로 유지합니다.
